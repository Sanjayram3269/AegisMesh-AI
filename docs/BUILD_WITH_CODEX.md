# Building AegisMesh with Codex

This file records engineering activity completed during the showcase upgrade. It does not claim that every historical line of the repository was generated by Codex.

## Starting point

The submitted application described intent analysis, identity verification, policy retrieval, risk scoring, escalation, signed execution tickets and tamper-evident auditing. The starting checkout was commit `8cb7fa5cc57d664749838fa79877873b97e36ce6`. The existing 116 tests passed locally.

Repository inspection found a simulated infrastructure/demo path, a Hugging Face Granite/mock factory, permissive identity tokens, request-supplied reviewer roles, missing expected-digest verification at the final executor, publicly returned lab credentials, and fixed provider health/latency fields. These findings were used to scope the upgrade.

## What Codex implemented

## Iteration evidence

1. The original tests were run before changes to establish a baseline.
2. Test fixtures were migrated to real test credentials; security checks were not disabled to preserve historical tests.
3. New approval tests caught an SQL placeholder mismatch before delivery; it was corrected and the suite rerun.
4. Browser checks caught horizontal overflow on mobile; grid sizing was corrected and the browser walkthrough rerun.
5. The first live planning run passed 3/7 task mappings. It exposed empty export field lists and the planner withholding approval requests. Strict output schemas, explicit examples and role separation improved the next run.
6. The schema iteration passed 6/7 under an initially overly restrictive external-request criterion: the model safely refused the external export rather than proposing it. The final criterion explicitly accepts safe refusal or a gateway-denied exact proposal. Both outcomes are distinguished in raw results.
7. The documented final live run passed 7/7 handcrafted cases in one pass. Initial and intermediate records remain available; this is development iteration, not a held-out generalization benchmark.
8. The flagship redesign replaced the six-page interface and added real WebGL stage selection. The extended browser check caught a navigation handler attached to the page body that closed receipt inspection on click; restricting handlers to navigation buttons corrected it. The live and Docker walkthroughs, eighteen viewport/page checks and 150 automated tests passed afterward.

## What to show a judge

Show one specific failure, the code change, and the test that verifies the corrected behavior. For example: start with a role string supplied by a caller, then show an API test where an agent account cannot approve an action even when it claims a manager role. Next show a legitimate separate manager approval succeeding.

Use the Git diff and final commits as the source of truth. Do not invent time saved, lines generated, real users, model accuracy, or security guarantees. Codex-generated work still needs developer review and domain validation.
